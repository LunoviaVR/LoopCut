# LoopCut IPC contract (frontend ↔ Rust)

Rust is canonical. Every type crossing the boundary derives `ts_rs::TS` with `#[ts(export)]` and lands in
`src/ipc/bindings/` (generated by `cargo test -p loopcut`; CI fails on drift). Frontend code calls commands only through
typed wrappers in `src/ipc/commands.ts` and never builds protocol URLs by hand (`src/ipc/protocol.ts`).

Conventions: command names are `snake_case`; arguments and fields are `camelCase` on the JS side
(Tauri converts command arguments; structs use `#[serde(rename_all = "camelCase")]`). Errors are returned as
`AppError { code: string, message: string, detail?: string }` (Rust `Result<T, AppError>`), never panics. `detail` is
omitted when Rust has none. Long jobs report through a `Channel<…>` argument or app events; every job is cancellable.

## Error codes

`not_found`, `network_path`, `unsupported_media`, `ffmpeg_failed`, `ffmpeg_missing`, `io`, `invalid_project`,
`newer_project`, `cancelled`, `not_implemented`, `invalid_argument`, `busy`, `gpu_failed` (no usable GPU renderer, or a
render failed), `gpu_lost` (the GPU device was lost; LoopCut uses the software renderer from then on),
`target_unreachable` (target-size mode could not fit the budget), `gif_failed` (the GIF encoder failed while writing an
export: gifski, the FFmpeg palette path or the GPU dither). Codes are stable: adding is allowed, renaming or removing is
not.

Preview failures keep the preview crate's codes: `preview_no_project`, `preview_invalid_project`,
`preview_invalid_request`, `preview_invalid_viewport`, `preview_sequence`, `preview_frame_out_of_range`,
`preview_timeout`, `preview_frame_unavailable`, `preview_decode`, `preview_cancelled`, `preview_render`,
`preview_spawn`.

**Paths.** Every path the webview names must be a drive-letter path (`C:\clips\a.mp4`, or with forward slashes) or a
UNC path (`\\server\share\a.mp4`). Device paths (`\\.\…`, `\\?\…`, including `\\?\GLOBALROOT\…` and the verbatim forms)
and relative paths are refused with `invalid_argument`. A clip path in a **project file** that fails this rule is not
an error: the clip is listed in `missingMedia` and never touched.

## Media

| Command | Args | Returns | Notes |
| --- | --- | --- | --- |
| `media_import` | `path: string`, `confirmNetwork?: boolean` | `ImportedMedia` | Probes with ffprobe, then mints a token for the canonical path. Network locations are refused with `network_path` unless `confirmNetwork` is true: a UNC path (`\\server\share`) or a drive letter mapped to a network share. The check runs on the raw path before canonicalization and again on the canonical path. |
| `media_thumbnails` | `token`, `count: number` (1–512), `height: number` (8–720) | `ThumbnailSet { width, height, times }` | Frames are fetched per index from the `loopcut` protocol. One set is kept per media file and height; a new set for the same height replaces the old one. `height` is the **real** output height (the request rounded down to an even number), and the protocol uses the same value. Sets share one RAM budget (256 MiB) across all media; the least recently used sets are evicted whole, and their protocol URLs then return 404 until the set is requested again. |
| `media_proxy_start` | `token`, `onProgress: Channel<ProxyEvent>` | `void` | Makes the timeline proxy if it does not exist. `ProxyEvent = {kind:"progress",value} \| {kind:"done",url} \| {kind:"error",error}`. **The channel is authoritative:** a failed or cancelled encode sends `error` and the command still resolves `Ok`. The command rejects only when it cannot start (`not_found`, `busy`, `ffmpeg_missing`, `io`). A hardware encode that fails is retried once on the CPU; a `progress` event with value `0` precedes the retry. A cancelled encode is reported and never retried. `LOOPCUT_FORCE_HW_FAIL` (see below) makes the hardware attempt fail before it starts. |
| `media_release` | `token` | `void` | Cancels the token's jobs (thumbnails, the probe or keyframe scan of its file, and the proxy encode the entry recorded when it started), then drops its caches. Runs on the blocking pool. Later protocol requests for the token return 404. Unknown tokens are ignored. |

A proxy job is keyed by its output file, so two tokens for one file never encode it twice. A proxy or thumbnail
result lands only on the entry that is still live for its token: when the token was released, or the file was imported
again while the encode ran, the result is dropped (a finished proxy stays in the cache for the next import). A
`media_proxy_start` whose token was released during the encode sends `error` with `not_found`. The encode registers its
job first and the entry records that job id; a token released (or its file imported again) between the registration
and the start of the encode gets the same `not_found` error, and nothing is encoded.

`ImportedMedia { token, path, fileName, info: MediaInfo, sourceUrl: string | null, needsProxy: boolean, proxyUrl: string | null, keyframeInterval: number | null }`

- `sourceUrl` is set when WebView2 can play the original (`info.video.webPlayable`), the source is at most 1080 px
  tall, and its longest GOP is **known** and at most 2 s. Otherwise `needsProxy` is true.
- `keyframeInterval: null` means the packet scan failed or was not run: the GOP is **unknown**, so `needsProxy` is true.
- A token is minted only for media that probed successfully. Every `loopcut-media` source request for a token without
  a live entry returns 404.

## Preview (Rust-rendered; see docs/architecture.md spike (b))

| Command | Args | Returns |
| --- | --- | --- |
| `preview_set_project` | `project`, `viewport: { width, height, dpr }` | `PreviewInfo { outputWidth, outputHeight, renderWidth, renderHeight, frames, fps, quality: "full" \| "reduced", delaysCs: number[] }` |
| `preview_frame` | `frame: number` (output frame index), `mode: "output" \| "source"`, `sourceTime?: number`, `maxWidth?: number`, `maxHeight?: number` | raw bytes: 8-byte header (`u32 LE width`, `u32 LE height`) + RGBA |
| `preview_play` | `fromFrame: number`, `loop: boolean`, `onFrame: Channel<ArrayBuffer>` | `void` — frames are pushed in the same header format, paced by the plan (GIF centisecond delays for GIF output, the output fps otherwise); late frames are dropped rather than drifting. Resolves when playback ends or is stopped; rejects with the playback error when playback stopped on one. |
| `preview_stop` | — | `void` |
| `preview_status` | — | `PreviewStatus { decodeProgress: number (0..1), failedRanges: number, fallbacks: DecodeFallback[], playing: boolean, lastError: string \| null }` |

- `preview_set_project` needs the clip's media to have been opened or imported (`not_found` otherwise). It rebuilds the
  preview engine only when the GPU context changed; otherwise the engine keeps its decoded frames. The viewport it
  receives is remembered for source frames without an explicit box.
- `preview_frame` in `mode: "output"` moves the decode window to the requested frame first (a seek). A `frame` past the end
  of the plan is `preview_frame_out_of_range`. `maxWidth` and `maxHeight` are checked to 1–8192 pixels (`invalid_argument`).
- `preview_play` starts with the decode window at `fromFrame`. A second `preview_play` replaces the first, which then
  resolves. `preview_stop` returns at once; the pending `preview_play` resolves when playback has ended. `preview_status`
  reports `playing` from the app's side of playback.
- `preview_status().lastError` is the engine's message text (`string`), not an `AppError`: the decode and playback
  errors it reports are not coded. Command-level failures are returned as `AppError` with the codes above.
- When playback stops on an error, `preview_play` rejects with that error mapped to a code: a lost GPU device is
  `gpu_lost` and switches the renderer to software (the same as a lost device anywhere else), and other failures keep
  their `preview_*` code. A stop, a newer play or the end of the plan resolves `void`, as before.
- `preview_set_project`, `preview_frame` and `preview_play` are registered jobs (`preview:project`, `preview:frame`,
  `preview:play`). `app_prepare_update` waits for a call that is already running, and a playback counts until it has
  ended. While the job registry is closed for an update, these three are refused with `busy` and the update message.
  `preview_stop` and `preview_status` still answer, also while an engine is being built. No engine or GPU context is
  built while closed; `app_resume_background` reopens the registry and the next preview builds what it needs.
- A GPU context that could not be created is remembered for 60 s, or until the hardware settings change. Preview and
  export requests in that time get the same `gpu_failed` error without a new attempt.
- `failedRanges`, `fallbacks` and `decodeProgress` are the engine's own figures for the current project.

- `mode: "output"` renders exactly what export produces for that output frame (crop, rotation, grade, captions), fitted
  into the viewport (never enlarged: a 480 px GIF shows at 480 device pixels unless the UI scales the canvas).
- `mode: "source"` renders the **uncropped**, display-oriented frame (source rotation plus project rotation and flips) at
  `sourceTime`, fitted into `maxWidth × maxHeight` (default: the viewport) — used by the crop tool and source scrubbing.
- Preview decodes the source uncropped at a resolution chosen from the viewport, so crop, grade, caption and timing
  edits re-render without re-decoding. A hardware decode failure falls back to the CPU and is reported in
  `preview_status().fallbacks`.

## Export

| Command | Args | Returns |
| --- | --- | --- |
| `export_presets` | — | `PlatformPreset[]` (versioned data; `verified`, `checkedOn`, `source`, `note` per preset) |
| `export_estimate` | `project` | `SizeEstimate { bytes, low, high, frames, basis: "sample" \| "full" }` — encodes up to three short windows with the real encoder and extrapolates (exact when the whole plan was encoded). |
| `export_start` | `project`, `outputPath`, `onEvent: Channel<ExportEvent>` | `jobId: string` |
| `export_cancel` | `jobId` | `void` |

`ExportEvent = {kind:"progress", framesDone, framesTotal, bytes} | {kind:"fallback", stage: "decode" \| "encode", from, to, reason} | {kind:"targetPass", pass, settings: string, bytes} | {kind:"done", path, bytes, seconds, frames} | {kind:"error", error: AppError}`.

- Output is written to `<outputPath>.partial` and renamed on success; cancel or failure deletes the partial file.
  An output path that resolves to the clip's own source file or to a `.loopcut` file is refused (`invalid_argument`).
- With `project.export.targetBytes` set, the exporter tries settings in a fixed order until the result fits, reporting
  each attempt as `targetPass` (`settings` names what the attempt used). Each step applies on top of the steps before
  it. GIF Quality: gifski quality 80, 70, 60; then frame rate 25, 20, 15, 12.5, 10 (only the rates below the project's);
  then width at 90 % down to 30 % of the output width; then lossy quality 80, 50, 30. GIF Fast and GIF GPU dither:
  palette 128, 64, 32 colours; then frame rate; then width. MP4 and WebM: quality 80, 60, 40, 20; then width. A plan
  longer than three 1.0 s windows is estimated over those windows first, and a step whose estimate is above the budget
  (by a per-engine margin) is ruled out without a real encode. Progress restarts from zero on every pass. When no
  setting fits, the export fails with `target_unreachable`; its message gives the smallest size of a real encode, or 0
  when every step was ruled out.
- `export_start` returns at once with `jobId` (`export:<id>`). The export runs on its own thread and is a registered job,
  so `app_prepare_update` cancels it. It is refused with `busy` while background work is closed for an update; the job
  is registered before any GPU context is used, so a refused start opens no device. If the webview stops accepting
  events (a channel send fails), the export is cancelled and ends with `error` `cancelled`.
- Events arrive in this order: any number of `progress`, `fallback` and `targetPass` events, then exactly one of `done`
  (sent after the file is in place, with the frame count of the file) or `error` (`cancelled` after `export_cancel`).
  Nothing follows the terminal event. A `targetPass` `bytes` is the estimate when its step was ruled out, and the real
  size when the step was encoded.
- `export_cancel` accepts only ids with the `export:` prefix that `export_start` returns (other ids are
  `invalid_argument`). An id with no running export, such as one that already finished, does nothing.
- `export_estimate` is per clip: a newer estimate for the same clip supersedes an older one. Claiming the newer one
  cancels the older one's token, so the older encode stops and returns `cancelled`. `export_estimate` samples 0.5 s windows.
- A `fallback` event with a stage other than `decode` or `encode` is not sent.
- No export returns `not_implemented` at present: every GIF engine is implemented, and a streamed source range asked for
  an earlier time restarts its stream instead of failing (see docs/architecture.md, Source frames).
- A plan that does not play its source in order (reverse, ping-pong, crossfade) whose source range does not fit the frame
  cache fails with `invalid_argument`; the message names the memory needed.
- A GIF encoder failure sends `error` with `gif_failed` (the message is "The GIF encoder failed."; the detail names the
  encoder's error).
- A lost GPU device during an export sends `error` with `gpu_lost`; the next GPU use creates the software renderer.

## Hardware & settings

| Command | Args | Returns | Notes |
| --- | --- | --- | --- |
| `hw_capabilities` | — | `Capabilities \| null` | The current record. `null` while the startup probe runs, or when no probe has finished yet. |
| `hw_probe` | `force: boolean`, `onProgress: Channel<ProbeEvent>` | `Capabilities` | Always runs a fresh probe (the cache is not consulted) and replaces the cached record. `force: true` also runs the speed benchmark (slower, more accurate). Rejects with `busy` while another probe runs, including the startup probe, and with `cancelled` when an update stops it. |
| `settings_get` | — | `AppSettings { hw: HwSettings, updates: UpdateSettings, cache: CacheSettings, general: GeneralSettings }` | |
| `settings_set` | `settings: AppSettings` | `void` | Clamped, then saved atomically. Frame-cache budgets apply at the next start. A change to `hw` drops the GPU context and the preview engine; the next preview or export builds them from the new settings, clears a software fallback that followed a device loss, and forgets a remembered GPU creation failure. |
| `cache_usage` | — | `{ bytes, files, path }` | |
| `cache_clear` | — | `void` | Clears the frame store and deletes cache files, except the frame store's folders (its spill files and the `owner.lock` that proves a live owner), proxies in use, and partial files while jobs run. |

`Capabilities` (bindings `Capabilities.ts`): `{ schema, ffmpegVersion, probedAtUnix, devices: DeviceCaps[], cpuEncode: EncodeCap[], warnings: string[] }`.
`DeviceCaps { device: GpuDevice, decode: DecodeCap[], scale: ScalerCap[], encode: EncodeCap[] }`. Every status is
`CapStatus = "ok" | "unsupported" | "failed"`.

`ProbeEvent = {kind:"step", label, done, total} | {kind:"result", label, ok}`.

**Cache and startup.** The record is stored in `<data>/hw-capabilities.json` with a key over the FFmpeg version line,
the probe logic version, the benchmark flag, and each adapter's identity, driver and indices. At startup a background
thread reads the FFmpeg version and the adapters, restores a stored record whose key is the benchmark key or the plain key
for the same FFmpeg and adapters (the benchmark key is tried first, because a benchmarked record also carries the speed
figures), and otherwise probes with a 20 s timeout per FFmpeg child and no benchmark. Adapter LUIDs are re-stamped from the
live adapters on load, because they change every boot. The FFmpeg version read runs as the `ffmpeg-version` job (only the
read, not the probe), so an update waits for it. When an update has already closed the job registry, startup skips the
version read and the probe.

**Fault injection.** `LOOPCUT_FORCE_HW_FAIL` is a comma-separated list of stages (`decode`, `scale`, `encode`, `all`) or
backend names (`amf`, `nvenc`, `qsv`, `cuda`, `d3d11va`). Matching hardware paths fail before they start, so every CPU
fallback can be exercised.

## App

| Command | Args | Returns | Notes |
| --- | --- | --- | --- |
| `app_info` | — | `AppInfo { version, ffmpegVersion, webview2Version?, logDir, dataDir }` | |
| `app_diagnostics` | — | `string` | Copyable report: versions, OS, WebView2, FFmpeg, folders, frame store, thumbnail cache usage, background jobs, shader compiler (DXC or FXC), **startup warnings**, GPU adapters, hardware capabilities (`select::describe`), settings, recent errors. |
| `app_prepare_update` | — | `void` | In this order: closes the job registry; stops playback and drops the preview engine and the GPU context (so the engine's decode children end and the device is released; nothing is recreated); cancels every job and waits up to 5 s for them to finish. | `app_resume_background` | — | `void` | Reopens the job registry after an update that did not install. The frontend calls it when an install fails. Refused with `busy` while an update is being prepared. |
| `app_open_path_arg` | — | `string \| null` | A `.loopcut` or media file passed on the command line at first launch. |

Event `app://open-path` (payload `string`) fires when a second instance forwards a file path. Relative arguments are
resolved against the second instance's working directory, and the path is trimmed. UNC and mapped network paths are never
forwarded.

**Startup never aborts.** An unresolvable app folder falls back to a temp folder; a folder that cannot be created, a
settings file that does not parse or is larger than 1 MiB (both are kept as `settings.json.corrupt-<unix-ms>`, so earlier copies are never overwritten, and defaults are used), and a log file that cannot be opened are recorded as
startup warnings. A frame cache that cannot be created falls back to RAM only under the temp folder (no disk spill). If even
that fails, frame caching is off. Warnings are shown by `app_diagnostics`.

**Logs.** `<logs>/loopcut.log` receives every backend `tracing` event (filter from `LOOPCUT_LOG`, default `info`); it is
truncated at startup once it exceeds 10 MB. `<logs>/frontend.log` receives frontend and `log`-crate messages through
`tauri-plugin-log`; it rotates at 10 MB and keeps the three most recent rotated files. Crashes write
`<logs>/crash-<ms>.txt`.

**Runtime warnings.** Problems found after startup (a GPU adapter that could not be opened and fell back to the software
renderer, a lost GPU device) are kept in memory and listed by `app_diagnostics` next to the startup warnings, together
with the renderer in use.

## Protocols

Built only through `protocolUrl(scheme, path)` in `src/ipc/protocol.ts` (Windows: `http://<scheme>.localhost/<path>`).

| Scheme | Path | Response |
| --- | --- | --- |
| `loopcut` | `thumb/<token>/<height>/<index>` | raw RGBA; headers `x-width`, `x-height` (the set's **real** height; an odd request height is normalized down to even) |
| `loopcut-media` | `src/<token>` | the original file with exact HTTP Range support (206/416) |
| `loopcut-media` | `proxy/<token>` | the generated proxy MP4 with Range support |

Status codes, both schemes:

- **200** full body; **206** partial body, `Content-Range` describes exactly the bytes sent (at most 4 MiB per response).
- **204** for `OPTIONS` preflight.
- **404** for an unknown, released or malformed token, an unknown route, a missing proxy, or a thumbnail that is not cached.
  Error bodies are the status reason text (`Not Found`).
- **405** with `Allow: GET, HEAD, OPTIONS` for any other method.
- **416** for a Range that starts past the end, and for a **malformed** Range (not a single `bytes=` range, or reversed).
  RFC 9110 lets a server ignore a Range it does not understand and send the whole body. LoopCut refuses instead, because
  a source can be many gigabytes.

Tokens are the only identifiers accepted. Responses carry `Access-Control-Allow-Origin` for the app origin only. The Vite
dev origin (`http://localhost:1420`) is accepted in debug builds only; a release build echoes the app origin alone.
